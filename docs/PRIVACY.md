# 隐私与豆瓣登录说明

## 一句话

**本项目没有任何服务器。** 没有后端、没有上报、没有统计、没有遥测——所有代码
都在这个仓库里，所有数据都只落在你自己的电脑和电视上。

## 为什么 Chrome 插件需要登录豆瓣？

海报墙需要每部电影的海报图片。这些图片在豆瓣的条目页上，而豆瓣对**未登录的
脚本请求**有严格限制（常见现象：请求返回 HTTP 200 但内容为空、或直接拒绝），
本地脚本批量抓取很快就会被限流。

插件的解决方案是：**在你自己的浏览器里、用你自己的登录态、按你设定的速度
（默认 ≥6 秒/部）逐个访问你本人本来就能打开的页面**。这和你自己翻豆瓣没有
本质区别，只是让浏览器替你翻。

## 我怎么确信它不会窃取我的信息？

不需要信任任何人，直接看代码——插件一共只有 4 个文件：

| 文件 | 干什么 |
|---|---|
| `manifest.json` | 权限声明（只请求豆瓣域名 + 下载） |
| `popup.html` / `popup.js` | 弹出界面：导入清单、开始/暂停、进度 |
| `background.js` | 开标签页、把图片存到下载目录 |
| `content.js` | 在豆瓣页面里检索条目、下载海报 |

全部逻辑可读。插件的网络请求只有两类目标：

1. `movie.douban.com` —— 条目检索和你本人能看的页面；
2. `*.doubanio.com` —— 海报图片本体。

没有任何其他域名，没有数据上报，没有分析统计。（`manifest.json` 的
`host_permissions` 和代码可逐行核对。）

## 数据都去了哪

- 海报图片 → Chrome 下载目录 `poster-wall/`；
- 清单与合并结果 → 本仓库目录的 `data/`；
- 电视端 → 电视上该应用自己的外部存储目录。

不上传、不同步、不留备份在别处。

## 不登录豆瓣行不行？

行。两种方式：

1. **直接用仓库自带的默认海报包**（`posters/`，320+ 张）——开箱即用；
2. 手动找图：按 `data/missing_list.md` 里的文件名，把海报图放进 `posters/`，
   跑一遍 `build_manifest.py` 自动收编。

## 一点提醒

抓取请保持人速（插件默认 ≥6 秒/部）。豆瓣的条目和海报版权归原作者，
本项目仅供个人欣赏与研究用途，请勿商用或再分发图片本身。
